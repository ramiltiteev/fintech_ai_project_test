# Инструкции для разработки

## Контекст и приоритеты

- Исходный PDF, `docs/source/assignment.txt` и архив внутренних записей `docs/internal/` хранятся локально и исключены из Git. Если доступен PDF, он — источник требований; порядок строк извлечённого текста местами отражает PDF-вёрстку. После клонирования использовать публичную документацию и contracts.
- Перед реализацией прочитать `docs/architecture.md`, `docs/financial-logic.md`, `docs/tax-rules.md`, `docs/chat.md`, `docs/validation.md`. Локальные требования и план в `docs/internal/` использовать при наличии; запуск и проверки не должны зависеть от них.
- MVP реализован в `src/fintech_copilot`, проверки — в `tests/`. Не выдавать фикстуры, mock-ответы и примеры trace за реальные LLM-прогоны; статус проверок — в `docs/validation.md`.
- Приоритет: grounding (35%), архитектура (30%), финансовая логика (20%), setup и тесты (15%). Уложить MVP в 3–5 часов; дополнительные функции вынести за пределы MVP.

## Правила кода

- Python 3.11+, Pydantic v2; Domain → Tools → Orchestration. Domain не импортирует LLM SDK, transport или prompts.
- Суммы — `Decimal`, входы/выходы JSON — строки с двумя знаками. `float`, NaN и Infinity в финансовых значениях запрещены.
- Периоды полуоткрытые `[start, end)`; стабильная сортировка `(posted_on, transaction_id)`; никакого `date.today()` в воспроизводимом сценарии.
- Инструменты считают из неизменяемого snapshot; агент не задаёт баланс, суммы, ставки или правила налогообложения.
- Tool registry — whitelist. Запрещены `eval`, динамические импорты по аргументам модели и произвольные file/network/shell tools.
- Каждый инструмент возвращает факты с источниками. Финальный JSON/Markdown получает числа только из результатов инструментов.
- Все три профиля и edge cases обязательны. Mock провайдера проходит настоящий цикл dispatcher/validation/result messages, не подменяет финансовые инструменты.
- Ключи только из окружения, реальные банковские/персональные данные не использовать; артефакты и `.env` не коммитить.
- Перед изменением контрактов обновить примеры и соответствующие спецификации. Не менять golden-ожидания под ошибочную реализацию.
- Проверять подготовку через `python3 scripts/check_preparation.py`; после реализации выполнять pytest, Ruff и mypy согласно плану.
- README на сдаче оставить коротким и описывать только проверенные команды и фактические ограничения.

## Завершение этапа

Указать выполненные проверки и ограничения в `docs/validation.md`; обновить локальный план, если он доступен. Платный live-прогон — отдельный явно выбираемый режим; без ключа mock работает полностью. Публикация GitHub и выбор модели остаются шагами сдачи.
