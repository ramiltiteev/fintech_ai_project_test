# Консольный финансовый агент

Чат сохраняет выбранную компанию, immutable snapshot, историю и кеш в памяти процесса. Модель выбирает инструменты, составляет план и пишет пояснения. Mock — сценарный эмулятор с настоящими финансовыми tools; его review тоже эмулируется и не доказывает качество реальной модели.

## Запуск

После [установки](setup.md):

```bash
.venv/bin/python -m fintech_copilot chat --company cloudscale-ai --provider mock --seed 42
```

Для настоящей модели экспортировать Gateway environment и явно выбрать `--provider live`; запросы могут быть платными. По умолчанию видны краткий план, прогресс tools и ответ. `--verbose` показывает scope, кеш, диагностику и token metadata.

Можно попросить разобрать расходы, затем проверить аномалии, уточнить вывод или подготовить полный отчёт. `/help` показывает команды, `/reset` очищает историю/кеш с сохранением snapshot, `/exit` завершает процесс. Новый процесс загружает текущий код и промпты.

## План и выполнение

`PlanAnalysis` — разрешённый инструмент оркестрации с mode answer/report и ordered steps: task, tool, scope. Он не выполняет финансовых расчётов. Перед анализом модель планирует все задачи в запрошенном порядке; полный отчёт требует четырёх финансовых tools за весь период. Узкий запрос может использовать один инструмент.

Шаг завершён только успешным exact-scope результатом, включая кеш. План можно расширить, сохраняя исходные шаги и порядок. Финансовый ответ должен использовать результат каждого шага в порядке плана. Если review обнаружил пропущенную задачу, цикл вновь предлагает планирование/tools в пределах бюджета.

## Обычный разговор и финансовый результат

Обычный разговор использует `ConversationReply`: модель отвечает простым текстом без финансовых ссылок. Проверка смысла допускает приветствия, объяснения методов и возможностей; утверждения о финансовых результатах компании требуют анализа и источников. Нумерация тем не считается финансовой суммой. Классификация намерения остаётся вероятностной.

После финансового плана writer получает отдельный контекст, текущий каталог и схему `ComposedReply`. Три типа parts:

- `text` — пояснение модели с пробелами, абзацами и Markdown; цифровые значения, citation templates и terminal controls запрещены.
- `fact` — существующий alias `f0`, `f1`, …; value, unit и format задаёт инструмент, не модель.
- `context` — company_name, period_start или period_end из snapshot; даты описывают всё покрытие, а не выбранный subperiod.

Иллюстрация структуры, не live evidence; alias должен существовать:

```json
{"kind":"answer","parts":[{"type":"text","text":"Операционные расходы — "},{"type":"fact","ref":"f0"},{"type":"text","text":"."}],"insights":[]}
```

Сервер собирает канонический `ChatReply.text` и полные references. В сохранённых fact parts остаётся настоящая пара result/fact IDs; при проверке весь payload повторно компилируется по tool results/dataset. Для report модель выбирает finding/action codes и полный evidence bundle; применяется тот же Synthesis grounding, что в batch-демо.

Отдельный semantic review проверяет атрибуцию, причины, рекомендации, финансовые количества словами и полноту запроса. Проверенные источники защищают подставленные значения, но review не гарантирует отсутствие ошибок любого свободного текста. Невалидный verdict или повторный отказ блокирует ответ. При ошибке успешные расчёты остаются в кеше; clarify/unsupported запрашивают недостающие данные.

## Артефакты и лимиты

По умолчанию trace находится в `artifacts/chat/trace.jsonl`. Узкий финансовый ответ сохраняется в answer.json/reply.md с facts и tool results. Полный отчёт — report.json/report.md и reply.json/reply.md; report.md содержит текст модели и финансовый audit. Обычные вопросы/ответы не сохраняются отдельными файлами. Ключи, raw model reasoning и отвергнутый текст не записываются в trace.

На сессию — до 20 пользовательских сообщений. На сообщение — 8 provider turns, включая review, 12 tools, 90 s на попытку, 300 s deadline, одна transient retry и один repair. Обычное сообщение расходует два provider turns: ответ и review. История не накапливает повторные tool payloads. Подтверждённые результаты и ограничения live-диалога — в [validation.md](validation.md).
