# Решения и допущения

Решения приняты для начала разработки без блокирующих уточнений. Они не являются дополнительными требованиями автора задания.

| ID | Неоднозначность | Решение MVP | Последствие |
|---|---|---|---|
| D01 | Нужен ли веб-сервис? | Python CLI, E2E, Docker | HTTP — после обязательных критериев |
| D02 | Провайдер и API-ключ не заданы | Mock по умолчанию; LiteLLM adapter для явно выбранной live-модели | SDK — optional dependency; тесты без сети |
| D03 | Формула runway не задана | Cash / positive average net operating burn, отдельно gross coverage | Нет деления только на расходы при наличии дохода |
| D04 | Нет starting balance | Обязательный opening balance на границе набора | Остаток восстанавливается без догадок |
| D05 | Наблюдаемый период короткий | Полные три календарных месяца, даты фиксированы | Сопоставимые месяцы, нет ложного annualization |
| D06 | Net 60/90 не доказать одними платежами | В invoice-derived receipts добавить `invoice_issued_on`, `payment_terms_days` | Lag — характеристика оплаченных счетов, не полная DSO |
| D07 | Q3 может означать будущее | Ретроспектива за июль–сентябрь; будущий прогноз вне MVP | Без AP/AR schedule будущий gap не обещается |
| D08 | Cross-border не равно неизвестная валюта | Все book amounts HKD; известна страна контрагента | FX/foreign-currency balances вне MVP |
| D09 | Налоговая декларация из cash ledger | Предварительная expense review schedule с недостающими сведениями | Налог, assessable profit и BIR51 поля не заполняются выдуманными суммами |
| D10 | Бинарное deductible/non-deductible | Добавить `review_required` | Категория сама по себе не доказывает вычет |
| D11 | Grounding произвольного текста | LLM выбирает finding/action codes и существующие refs; сервер рендерит текст | Проверяемая точность чисел ценой меньшей свободы текста |
| D12 | Версии библиотек не заданы | Python 3.11+, Pydantic v2; точные версии фиксировать после установки и тестов | Не создавать неподтверждённый lockfile |
| D13 | Требование GitHub | Подготовить сдачу локально, публикация отдельным действием | URL репозитория пока отсутствует |

## Что уточнить перед расширением

- Какой провайдер/модель и бюджет live API доступны?
- Есть ли утверждённый basis period, юрисдикции, бухгалтерские финансовые отчёты и подтверждения расходов?
- Нужны ли прогноз AP/AR, валютные позиции, consolidated accounts или HTTP API?

Ответы не блокируют MVP в текущем согласованном объёме.

## Уточнения реализации MVP

- D14: связанные финансовые функции собраны в одном domain/finance.py, provider adapters — в orchestration/providers.py. Snapshot передаётся dispatcher как frozen Dataset; отдельный repository layer не нужен для одного in-memory run.
- D15: неизвестное имя инструмента возвращает protocol rejection без tool_result_id. Исходный tool result enum остаётся закрытым; ошибки известных tools используют стандартную schema и серверный scope.
- D16: точные offline dependency versions проверены локально; clean install/wheel/Docker и optional live SDK остаются открытыми. Конкретную live-модель не выбирали и API не вызывали.
