# ADR 0001: отчёты из детерминированных фактов

Статус: принято для MVP. Дата: 2026-10-06.

## Проблема

Главный критерий задания — отсутствие выдуманных сумм. Prompt с просьбой «не галлюцинировать» и сравнение встречающихся чисел не проверяют ни источник, ни смысл вывода.

## Решение

Tools создают каталог фактов с `(tool_result_id, fact_id, value, unit, transaction_ids)`. LLM возвращает только ранжированные finding codes, action codes и ссылки на существующие факты. Валидатор проверяет происхождение и условия вывода. JSON и Markdown собираются сервером из тех же проверенных значений и фиксированных текстовых шаблонов.

Свободный числовой prose не входит в контракт synthesis. Company name, период и transaction IDs тоже берутся из контекста сервера. Непроверенный результат LLM не публикуется; при исчерпании лимита возвращается частичный tool-based отчёт с явным статусом.

## Альтернативы

Свободный Markdown потребовал бы более сложной semantic verification и всё равно не гарантировал бы точности. Предварительный расчёт всех инструментов без model tool calls упростил бы приложение, но не продемонстрировал бы многошаговую оркестрацию.

## Последствия

LLM выбирает связку «факт → управленческий вывод → действие», а арифметика и условия риска живут в бизнес-логике. Формулировки ограничены небольшим набором шаблонов. Корректность фактов зависит от расчётных tools, поэтому golden-tests и проверка evidence обязательны. За пределами MVP можно добавить свободный narrative отдельным неподтверждённым приложением.
